The 4 previously-skipped tests — now fixed for real

Each one turned out to be fixable properly rather than just excludable. One pair uncovered a live production bug along the way.

Fixed — a real production bug, not just a test gap

test_health_endpoint_format & test_ready_endpoint_format tested /health//ready routes that didn't exist. Turned out docker-compose.yml's healthcheck: and scripts/smoke-test.py both already call GET /health expecting 200 — so any Docker/HTTP deployment's healthcheck has been silently failing. Implemented both routes for real (_register_health_routes() in mcp_server/server.py, using FastMCP's custom_route), verified live with curl against a running server, then tested via an ASGI test client — 4 real tests now, including /ready correctly returning 503 when a remote-profile deployment has no auth configured.

Fixed — the broken import, then replaced two vacuous tests

test_client_connect_stdio & test_client_initialization never actually ran — the module-level import named a class, StdioClientTransport, that has never existed in the Python MCP SDK (it's the TypeScript SDK's class name; the real API is stdio_client + StdioServerParameters). Even once fixed, both bodies only checked ClientSession is not None — true of any class. Replaced with tests that spawn the real server and drive it through the official SDK client: connect, initialize, list all 13 tools, call one and check the result.

Also removed, as genuinely unused: InitializeResult, Tool, patch, AsyncMock, Any, Dict — none referenced anywhere in the file outside their own import line.

MCP spec compliance audit — 2 more gaps, found by reading the spec, not the tests

After every bug above was fixed, a separate pass checked the server against the actual MCP specification instead of this project's own test suite. Confirmed already-correct: stdout hygiene, error-handling semantics, and DNS-rebinding defaults for the default localhost deployment. Two real gaps found and fixed — neither was reachable by any test above, because they're missing protocol metadata and missing transport config, not input-validation bugs.

Fixed — zero tool annotations, on all 13 tools

The spec defines readOnlyHint/destructiveHint/idempotentHint/openWorldHint specifically so a client can tell a safe read apart from a state-changing write before prompting a human for approval. Every tool here looked identical to a client trying to make that call. Added a TOOL_METADATA map applied to both the stdio and HTTP-transport instances: 12 generators/lookups get readOnlyHint=True; update_versions — the one tool that mutates server state — is the sole exception.

Fixed — DNS-rebinding protection silently disabled for remote deployment

The SDK auto-enables Origin/Host validation only for 127.0.0.1/localhost/::1. Binding 0.0.0.0 — required inside a container, and what the project's own docker-compose.yml "remote" profile already does — silently turns that protection off. Added _build_transport_security() plus two new env vars (DEVOPS_OS_ALLOWED_HOSTS/DEVOPS_OS_ALLOWED_ORIGINS): enables real protection when a deployment configures its allowlist, logs a loud warning when it hasn't — there's no safe default to guess for a domain the server knows nothing about.
